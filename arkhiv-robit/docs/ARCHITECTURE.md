# Архітектура застосунку «Архів курсових і дипломних робіт»

Документ описує, як влаштовано застосунок. Його можна використати як основу для розділів
«Проєктування» та «Реалізація» пояснювальної записки.

## 1. Постановка задачі

Потрібна вебсистема для зберігання курсових і дипломних робіт у хмарі з такими вимогами:

1. Роботи завантажують **викладачі**, їх може бути кілька.
2. Викладачам **не потрібно реєструватися** і створювати акаунти.
3. Файли зберігаються у **хмарному сховищі** з великим обсягом пам'яті.
4. Опис робіт зберігається в **базі даних**.
5. Роботи можна знайти **за назвою групи та роком**.
6. Інтерфейс має бути простим і зрозумілим, зокрема на телефоні.
7. Застосунок розміщується в хмарі, **не на GitHub**.

## 2. Загальна архітектура

Застосунок побудовано за класичною **трирівневою архітектурою**:

```
┌────────────────────────┐
│   Браузер користувача  │   HTML + CSS (сторінки формує сервер)
└───────────┬────────────┘
            │ HTTPS
┌───────────▼────────────┐
│  ASP.NET Core (C#)     │   Рівень логіки:
│  Razor Pages           │   • сторінки (Pages/)
│                        │   • сервіси (Services/)
│                        │   • вхід за кодом, права доступу
└─────┬─────────────┬────┘
      │ EF Core     │ S3 API
┌─────▼──────┐ ┌────▼───────────────┐
│ PostgreSQL │ │ Хмарне сховище S3  │  Рівень даних:
│ (опис робіт│ │ (файли робіт)      │  • база даних — метадані
│  викладачі)│ │ R2 / B2 / S3       │  • сховище — самі файли
└────────────┘ └────────────────────┘
```

**Чому файли не зберігаються в базі даних.** Бази даних погано підходять для великих файлів (десятки мегабайт),
а хмарні бази дорогі в перерахунку на гігабайт. Object storage (S3) створено саме для файлів:
10 ГБ безкоштовно, далі близько 0,015 $ за ГБ на місяць. У базі лежить лише опис роботи і ключ файлу у сховищі.

## 3. Вибір технологій

| Рішення | Альтернативи | Чому обрано |
|---|---|---|
| C# / ASP.NET Core 10 | Python/Django, PHP, Node.js | Сувора типізація, висока швидкодія, LTS-підтримка до листопада 2028, нативна підтримка в Azure |
| Razor Pages | MVC, Blazor, React + API | Для застосунку зі сторінками та формами це найпростіша модель: одна сторінка — один клас |
| Entity Framework Core | Dapper, чистий SQL | Робота з таблицями як з об'єктами C#, підтримка різних СУБД без зміни коду |
| PostgreSQL | MySQL, SQL Server | Безкоштовні хмарні тарифи (Neon, Supabase), відкрита ліцензія |
| SQLite (розробка) | — | Не потребує встановлення сервера БД |
| S3-сумісне сховище | Azure Blob, Google Drive | Відкритий стандарт: той самий код працює з Cloudflare R2, Backblaze B2, Amazon S3, MinIO |
| Вхід за кодом доступу | Логін і пароль, OAuth | Вимога «без акаунтів»; простіше для викладачів, при цьому видно, хто що завантажив |

## 4. Модель даних

```
┌──────────────────────────┐          ┌──────────────────────────────┐
│ Teachers                 │          │ Works                        │
├──────────────────────────┤          ├──────────────────────────────┤
│ Id           int  PK     │ 1      N │ Id                  int  PK  │
│ Name         text        │◄─────────┤ UploadedByTeacherId int  FK? │
│ CodeHash     char(64) UQ │          │ Type                int      │  1 — курсова, 2 — дипломна
│ IsActive     bool        │          │ Title               text     │  тема
│ CreatedAt    timestamp   │          │ StudentName         text     │
└──────────────────────────┘          │ GroupName           text  IX │  «КН-41»
                                      │ Year                int   IX │
                                      │ Supervisor          text?    │
                                      │ Description         text?    │
                                      │ FileKey             text  UQ │  ключ у сховищі
                                      │ FileName            text     │  оригінальна назва
                                      │ FileSize            bigint   │
                                      │ ContentType         text     │
                                      │ SearchText          text     │  для пошуку
                                      │ DownloadCount       int      │
                                      │ UploadedByName      text     │
                                      │ CreatedAt, UpdatedAt         │
                                      └──────────────────────────────┘
```

- Індекс `(Year, GroupName)` пришвидшує основний сценарій пошуку «група + рік».
- Якщо викладача видалити, `UploadedByTeacherId` стає `NULL` (`ON DELETE SET NULL`), а робота залишається в архіві.
- Таблиця `DataProtectionKeys` (службова) зберігає ключі шифрування cookie.

### Нормалізація даних

Щоб пошук за групою працював незалежно від того, як викладач написав назву, група приводиться до єдиного вигляду
(`TextNormalizer.Group`): `«кн 41»`, `«КН – 41»`, `«кн-41»` → `«КН-41»`.
Для текстового пошуку зберігається поле `SearchText` (тема, студент, керівник і група в нижньому регістрі).
Так пошук однаково працює і в PostgreSQL, і в SQLite.

## 5. Ролі та права доступу

Облікових записів немає. Роль визначається тим, **який код** людина ввела на сторінці входу.

| Дія | Гість | Викладач | Адміністратор |
|---|:-:|:-:|:-:|
| Переглядати каталог, шукати, скачувати | ✔ (*) | ✔ | ✔ |
| Додавати роботи | — | ✔ | ✔ |
| Редагувати та видаляти роботи | — | лише свої | усі |
| Створювати і вимикати коди викладачів | — | — | ✔ |
| Бачити статистику | — | — | ✔ |

(*) Якщо задано `Archive__ViewCode`, гість спершу має ввести код перегляду.

Реалізація (`Program.cs`, `Services/Roles.cs`):
- Політики авторизації `View`, `Upload`, `Admin` призначаються сторінкам через `Conventions.AuthorizeFolder/AuthorizePage`.
- Право «лише свої роботи» перевіряє метод `ClaimsPrincipal.CanManage(work)`.

### Як працює вхід за кодом

```
Викладач вводить «7f3k 92qa»
        │
        ▼
AccessCodes.Normalize  →  «7F3K92QA»
AccessCodes.Hash       →  SHA-256  →  «A94F…»
        │
        ▼
Порівняння з кодом адміністратора (сталий час) ─┐
Пошук Teachers.CodeHash = «A94F…» AND IsActive ─┼─► знайдено → cookie з роллю
Порівняння з кодом перегляду                   ─┘   і «відбитком» коду (Stamp)
```

При кожному запиті `AccessService.IsStillValidAsync` перевіряє, що викладач досі активний і його код не змінювався
(відбиток у cookie збігається з поточним хешем). Тому **«Вимкнути»** і **«Новий код»** в адмін-панелі
діють миттєво: людину буде виведено з системи при наступному ж запиті.

## 6. Основні сценарії

### Завантаження роботи

```
Викладач ─► POST /Works/Upload (форма + файл)
             │
             ├─ перевірка полів (DataAnnotations) і файлу (FileRules.Validate)
             ├─ ключ файлу: works/2026/<GUID>.pdf  (лише латиниця, без збігів)
             ├─ IFileStorage.SaveAsync ─► хмарне сховище
             ├─ INSERT INTO Works ─► PostgreSQL
             │     └─ якщо запис у БД не вдався — файл зі сховища видаляється
             └─ переадресація на сторінку роботи
```

### Пошук і скачування

```
Користувач ─► GET /?group=КН-41&year=2025
               └─ WorkFilter.Apply → SELECT … WHERE GroupName='КН-41' AND Year=2025

Користувач ─► GET /download/15
               ├─ DownloadCount + 1
               ├─ S3: тимчасове підписане посилання (10 хв) → переадресація,
               │      файл іде напряму зі сховища, не навантажуючи сервер
               └─ Local: файл віддає сам сервер
```

## 7. Шаблон «Стратегія» для сховища файлів

Код, що працює з файлами, залежить лише від інтерфейсу `IFileStorage`:

```csharp
public interface IFileStorage
{
    Task SaveAsync(string key, Stream content, string contentType, CancellationToken ct = default);
    Task<string?> GetDownloadUrlAsync(string key, string fileName, CancellationToken ct = default);
    Task<Stream> OpenReadAsync(string key, CancellationToken ct = default);
    Task DeleteAsync(string key, CancellationToken ct = default);
}
```

Конкретна реалізація (`LocalFileStorage` або `S3FileStorage`) вибирається при старті за налаштуванням `Storage__Provider`
і передається сторінкам через **впровадження залежностей** (Dependency Injection). Щоб перейти на інше сховище,
достатньо змінити налаштування, код сторінок змінювати не потрібно.

## 8. Безпека

| Загроза | Захист |
|---|---|
| Витік бази даних | У базі лише SHA-256 хеші кодів |
| Підбір коду | 31⁸ ≈ 8,5·10¹¹ варіантів + обмеження 10 спроб за 5 хвилин з IP |
| Атака за часом відповіді | `CryptographicOperations.FixedTimeEquals` |
| CSRF (підробка запитів) | Антифорджері-токени в усіх формах (вбудовано в Razor Pages) |
| XSS | Razor автоматично екранує весь текст користувача |
| Завантаження шкідливих файлів | Білий список розширень, обмеження розміру |
| Вихід за межі папки (`../`) | `LocalFileStorage.ResolvePath` перевіряє шлях |
| Прямий доступ до файлів | Приватний кошик, тимчасові підписані посилання |
| Викрадений або загублений код | «Новий код» / «Вимкнути» — сесії завершуються одразу |

## 9. Тестування

Проєкт `tests/ArkhivRobit.Tests` містить 54 автоматичні тести (xUnit):

- **Модульні тести:** генерація та перевірка кодів, нормалізація груп, перевірка файлів,
  перетворення рядка підключення до PostgreSQL, пошук за фільтрами (на справжній SQLite у пам'яті).
- **Інтеграційні тести** (`WebApplicationFactory`): застосунок запускається повністю, запити йдуть як із браузера.
  Перевіряються: публічний каталог; вхід за невірним кодом; повний сценарій «адміністратор створює код → викладач
  завантажує → гість знаходить за групою та роком і скачує»; заборона редагувати чужі роботи; відхилення `.exe`;
  закритий архів із кодом перегляду; блокування підбору кодів.

Запуск: `dotnet test` у папці `arkhiv-robit`.
